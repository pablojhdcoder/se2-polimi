\subsection{Manual Testing of Path and Trip Recording}
\label{subsec:manual_path_trip_results}
We exercised automated path recording by walking around our residence. \textbf{Behaviour was very good overall}, with two exceptions:
\begin{itemize}
    \item \textbf{Keyboard in path description:} The keyboard cannot be dismissed while writing the path description unless the user taps the Manual/Automatic mode button. The fix is straightforward (e.g.\ dismiss keyboard on tap outside or provide an explicit dismiss control).
    \item \textbf{Trip recorded over the path regardless of route:} When recording a trip, even if the user does not follow the path route, the trip is still recorded as if it were on the path. This may be intentional (e.g.\ snapping to the path) or a bug; we report it as observed behaviour for the team's consideration.
\end{itemize}
These observations are reflected in ``Areas for Improvement'' (Chapter~\ref{ch:acceptance_test_cases}).

\section{Additional Notes}
\label{sec:additional_notes}
\begin{itemize}
    \item Server-side behaviour is well covered by unit and integration tests; requirements implemented in the backend are validated by these runs.
    \item N/R (Not Run) is used for behaviour that depends on the app UI or client logic (e.g.\ cycling detection, navigation, in-app alerts). The app suite did not discover tests on our Windows setup because of the Jest \texttt{testMatch} pattern; executing the app tests on Linux or macOS would give full acceptance coverage for R8--R11, R14--R15, R22--R23, R39, R40.
    \item Snapping (OSRM) and geocoding (Nominatim) are exercised by backend unit/integration tests; \texttt{RUN\_LIVE\_TESTS=1} can be used to validate against live external services.
\end{itemize}

\section{Areas for Improvement}
\label{sec:areas_for_improvement}
\begin{itemize}
    \item \textbf{Prisma: support both PostgreSQL URL and Accelerate:} The default \texttt{prisma-client.ts} could support both Accelerate and a direct \texttt{postgresql://} URL (via \texttt{@prisma/adapter-pg}), enabling local runs without Prisma Accelerate. A possible implementation is in Section~\ref{subsec:database_setup}, Chapter~2.
    \item \textbf{JWT and Redis in README:} The README should state that \texttt{JWT\_SECRET} and \texttt{JWT\_REFRESH\_SECRET} must be non-empty. For local runs without Docker, it should document \texttt{REDIS\_HOST=localhost} and how to start Redis (Docker or system install).
    \item \textbf{Order of operations:} The README could spell out that a valid \texttt{DATABASE\_URL} and applied migrations are needed before \texttt{npm run dev}.
    \item \textbf{Prisma \texttt{DATABASE\_URL}:} With \texttt{prisma.config.ts}, \texttt{DATABASE\_URL} must be set (e.g.\ a placeholder) before \texttt{prisma generate}; this could be mentioned in the README.
    \item \textbf{Manual path constraints:} Manual path creation could enforce or warn when paths cross buildings or invalid areas (e.g.\ validate or snap to road/cycle network).
    \item \textbf{Snapping 500 errors:} On OSRM 500, the app logs \texttt{Failed to snap segment}. Clearer user feedback and a retry or fallback (e.g.\ keep unsnapped segment) would let path creation continue.
    \item \textbf{Keyboard in path description:} The path description keyboard could be dismissible without tapping the Manual/Automatic button (e.g.\ tap-outside or a dismiss control).
    \item \textbf{Trip recording vs.\ path route:} When the user does not follow the path route, the trip is still recorded over the path. If that is intentional (snapping), it could be documented; otherwise consider storing the actual route or warning the user.
    \item \textbf{Backend \texttt{npm test} script:} A cross-platform way to set \texttt{NODE\_OPTIONS} (e.g.\ \texttt{cross-env} or a small script) would make \texttt{npm test} work on Windows and Unix.
    \item \textbf{App test runner on Windows:} The Jest \texttt{testMatch} (or equivalent) could be adjusted so that \texttt{npm test} discovers tests in \texttt{tests/unit} and \texttt{tests/integration} on Windows.
\end{itemize}
