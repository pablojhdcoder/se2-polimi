\subsection{Manual Testing of Path and Trip Recording}
\label{subsec:manual_path_trip_results}

\textbf{Testing by walking around our residence (physical device):}
We exercised automated path recording by walking around our residence. \textbf{Behaviour was very good overall}, with two exceptions:
\begin{itemize}
    \item \textbf{Keyboard in path description:} The keyboard cannot be dismissed while writing the path description unless the user taps the Manual/Automatic mode button.
    \item \textbf{Trip recorded over the path regardless of route:} When recording a trip, even if the user does not follow the path route, the trip is still recorded as if it were on the path. This may be intentional (e.g.\ snapping to the path) or a bug; we report it as observed behaviour for the team's consideration.
\end{itemize}

\textbf{Testing on the emulator (Create path, manual draw mode):}
When testing the ``Create path'' flow in manual draw mode (drawing the route on the map by tapping or dragging) on the emulator, we observed:
\begin{itemize}
    \item \textbf{Console error ``Maximum update depth exceeded'':} The app sometimes displayed a red console error when React's maximum update depth is exceeded.
    \item \textbf{Path alignment in manual mode:} When adding a path manually, snapping to the road/cycle network sometimes fails with \texttt{WARN Failed to snap segment [AxiosError: Request failed with status code 500]}. Because of this failure, the segment is not snapped and the path can end up crossing buildings or other invalid areas; the user can effectively draw anywhere. The app continues without aligning the drawn segment. Improving the reliability of the snapping service and/or user feedback would avoid this.
\end{itemize}
These observations are reflected in Section~\ref{sec:areas_for_improvement} (Areas for Improvement).

\section{Areas for Improvement}
\label{sec:areas_for_improvement}
\begin{itemize}
    \item \textbf{Prisma: support both PostgreSQL URL and Accelerate:} The default \texttt{prisma-client.ts} could support both Accelerate and a direct \texttt{postgresql://} URL (via \texttt{@prisma/adapter-pg}), enabling local runs without Prisma Accelerate. A possible implementation is in Section~\ref{subsec:database_setup}.
    \item \textbf{JWT and Redis in README:} The README should state that \texttt{JWT\_SECRET} and \texttt{JWT\_REFRESH\_SECRET} must be non-empty. For local runs without Docker, it should document \texttt{REDIS\_HOST=localhost} and how to start Redis (Docker or system install).
    \item \textbf{Order of operations:} The README could spell out that a valid \texttt{DATABASE\_URL} and applied migrations are needed before \texttt{npm run dev}.
    \item \textbf{Console error ``Maximum update depth exceeded'' (Create path):} In manual draw mode (drawing the route on the map by tapping or dragging), the app can display a red console error when React's maximum update depth is exceeded.
    \item \textbf{Path alignment in manual mode:} When snapping fails, segments are not aligned to the road/cycle network and paths can cross buildings or invalid areas.
    \item \textbf{Keyboard in path description:} The path description keyboard could be dismissible without tapping the Manual/Automatic button (e.g.\ tap-outside or a dismiss control).
    \item \textbf{Trip recording vs.\ path route:} When the user does not follow the path route, the trip is still recorded over the path.
    \item \textbf{Backend \texttt{npm test} script:} A cross-platform way to set \texttt{NODE\_OPTIONS} (e.g.\ \texttt{cross-env} or a small script) would make \texttt{npm test} work on Windows.
    \item \textbf{App test runner on Windows:} The Jest \texttt{testMatch} (or equivalent) could be adjusted so that \texttt{npm test} discovers tests in \texttt{tests/unit} and \texttt{tests/integration} on Windows.
\end{itemize}
